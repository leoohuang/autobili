## Iteration #2026-07-04

### 改进内容：为 Bilibili 字幕探测添加并发上限控制

**问题：**
`probeSubtitles` 函数会对视频的每一个分 P 并发发起字幕 API 请求。如果视频有 50+ 个分 P，会同时向 Bilibili 字幕 API 发出 50+ 个并发请求，容易触发 IP 限流甚至被临时封禁。

**解决方案：**
在 `lib/bilibili.ts` 中引入一个轻量级 `Semaphore` 类，通过它限制最多同时进行 5 个字幕 API 请求（`MAX_CONCURRENT_SUBTITLE_REQUESTS = 5`）。所有分 P 的字幕探测仍然并发启动，但通过信号量控制实际并行度不超过 5，避免触发 Bilibili 的速率限制。

**关键改动：**
1. 新增 `Semaphore` 类（轻量级，无外部依赖）：`acquire()` 阻塞直到有空闲槽位，`release()` 释放槽位
2. `probeSubtitles` 中：将原来直接 `for` 循环改为 `Promise.all(pages.map(...))`，所有分 P 同时启动，通过 semaphore 控制实际并发数
3. `pageAttempts` 数组改为预先分配，保证结果按原始分 P 顺序记录
4. `MAX_CONCURRENT_SUBTITLE_REQUESTS` 常量设为 5
