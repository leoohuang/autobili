### 改进内容
**文件**: `lib/bilibili.ts`（+ `README.md` 文档同步）

**问题（Bug 修复）**: `resolveBvidDetails()` 把整个用户输入直接丢给 `new URL()`。
B 站手机 App「复制链接」产出的是**分享文案**而不是裸链接，例如：

```
【我为什么劝你别考研-哔哩哔哩】 https://b23.tv/8kNq2Xv
```

这种输入：
1. 文案里**没有 BV 号**，`extractBvid()` 直接匹配失败；
2. `new URL("【...】 https://b23.tv/8kNq2Xv")` 抛异常 → 返回 `invalid_input`；
3. 前端提示「无法识别 B 站视频链接」。

结果是**最常见的一种粘贴方式 100% 失败**。同理，省略 `https://` 的裸链接
（`b23.tv/8kNq2Xv`）也一律失败。而 `bilibili.com` 长链的分享文案能侥幸工作，
只是因为文案里恰好带 BV 号被 `直接匹配` 捞回来了——b23.tv 短链没有这个兜底。

**修复**: 新增 `extractUrlCandidate()`，在 `new URL()` 之前先从任意文本中**抽取**出 URL：
- `URL_IN_TEXT_PATTERN`：匹配内嵌的 http(s) URL，字符类排除 CJK 标点区
  （`\u3000-\u303f`、`\uff00-\uff65`），避免把「，。】）」粘进 URL。
- `SCHEMELESS_URL_PATTERN`：无 scheme 时，识别 `b23.tv/...` 与 `*.bilibili.com/...` 并补 `https://`。
- `stripTrailingNoise()`：剥掉尾部标点噪声。
- 抽不出候选 URL 时直接返回 `invalid_input`，不发起任何请求。

**安全性**: 原有 SSRF 主机白名单（`isAllowedResolveUrl`）保持在抽取之后执行，未被削弱。
已验证 `http://169.254.169.254/...`（云元数据端点）和
`https://evil.com/?u=https://b23.tv/x`（把合法域名塞进 query 试图绕过）均仍被拒绝
——正则是贪婪匹配，抓到的是 `evil.com` 整条 URL 而非内嵌的 b23.tv，不存在绕过。
